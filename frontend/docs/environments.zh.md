# 测试环境

在 **运行环境**(Runner Envs)中注册运行测试的机器:名称、SSH 主机、SSH 用户名、
SSH 私钥,以及环境设置脚本。用 **Test** 验证连通性,用 **Run command** 交互式地
尝试命令,或在机器上派发一次手动测试(见 [Runner 与任务](#/docs/runner-strategy))。

服务器通过 SSH 连接环境以上传源码(一个 tar 流,解压到
`~/.md-builder/tasks/<sha12>`)并运行构建/测试脚本 —— 见
[Runner 与任务](#/docs/runner-strategy)。

## 谁能看到、谁能修改

环境是**全站共享的资源池**。一次 push 会被派发到 tags 匹配
`md-builder.yaml` 中某个 entry 的环境上,而不管那台机器是哪个账号注册的 ——
因此每个已登录用户都能在列表里看到全部环境,每个环境也都是 dashboard 矩阵的
一列(列头会标注它的 owner)。

区别在于你能对这一行做什么:

| | Owner | 管理员 | 其他用户 |
|---|---|---|---|
| 在列表和 dashboard 中可见 | 是 | 是 | 是 |
| 编辑、启用/禁用、删除 | 是 | 是 | 否(只读) |
| **Test**、**Run command**、**Run script**(使用存储的私钥) | 是 | 是 | 否 |

被拒绝的写操作返回 `403` 并说明原因;不属于你的行显示为只读,而不是给出点了
必然失败的按钮。owner 就是创建该环境的账号,且不会变更。

可见不等于可选:列表和 dashboard 展示整个资源池,而 **Run command** 页面上的
选择框只给出你有权在上面运行的环境。

| 入口 | 使用哪些环境 |
|---|---|
| 环境列表(运行环境)、dashboard 矩阵 | 全站所有环境 |
| **Test**、**Run command**(exec / script 标签) | 你有权使用的 —— 自己的,管理员则是全部 |
| *Manual test* 标签 —— **手动派发**(自定义 stage 命令) | 你有权使用的(规则同上) |
| *Manual test* 标签 —— **yaml 矩阵触发**、webhook push | 所有已启用环境中按 tags 匹配出来的 —— 与归属无关 |

因此管理员可以清理没人维护的环境 —— 比如 `md-builder seed` 留下的 demo 行
(属于用户 `demo`),普通用户既不能禁用也不能删除它们。

## 前置条件

每个环境需要:

- `bash`、`tar`、`gzip` 和 `timeout`(coreutils)—— 每个任务都会用到。
- 构建与测试命令所需的工具链(cmake、编译器、python 等),由机器管理
  员自行安装。

环境**不需要 git**,也不需要任何仓库访问权限:服务器自行克隆代码
仓库,再把工作树传送过去。

## 标签

每个环境带有一个或多个**标签**(小写单词,如 cpu、gpu、cuda、mpi)。
标签是测试矩阵挑选环境的方式:矩阵条目列出所需的标签,md-builder 挑选
*一个* 标签覆盖全部要求的环境。规则:

- 匹配是超集匹配且大小写不敏感:拥有 cpu、mpi 标签的环境满足只要求
  cpu 的条目。
- 多余的无关标签不影响匹配;有多个候选时,"最紧凑" 的环境胜出(额外
  标签最少,其次按名称排序)。
- 每个条目只在一个环境上运行;若没有环境匹配,该条目被跳过(计入
  派发响应的 entriesSkipped,不算错误)。
- 环境**启用**后才能接收任务;停用的环境在仪表板上保持置灰。

## 环境设置脚本

每个环境可以携带一段 bash **环境设置脚本**(在环境表单中编辑)。派发时
它被写入任务目录,文件名为 `md-builder-env-<hash>.sh`(哈希由内容决定,
因此编辑脚本会改变文件名),并且被**每个阶段脚本** —— 构建、单元测试和
每个回归用例 —— 在阶段命令运行之前 source:

```bash
module load gcc/13 openmpi/4.1
export CXX=mpicxx
source /opt/profiles/intel.sh
```

用它完成 module 加载、编译器导出、virtualenv 激活 —— 阶段命令所需的
一切环境准备。因为它在脚本导言的最后运行,甚至可以覆盖内置变量和
yaml 变量(见[内置环境变量](#/docs/test-matrix))。

没有脚本的环境也没问题:阶段脚本会记录一条警告(`env script ... not
found`)并照常运行。
