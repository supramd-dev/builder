# 测试环境

在 **User center** 中注册运行测试的机器:名称、SSH 主机、SSH 用户名和
SSH 私钥。用 **Test** 验证连通性,用 **Run command** 交互式地尝试命令,
或在机器上派发一次手动测试(见 [Runner 与任务](#/docs/runner-strategy))。

服务器通过 SSH 连接环境以上传源码(一个 tar 流,解压到
`~/.md-builder/tasks/<sha12>`)并运行构建/测试脚本 —— 见
[Runner 与任务](#/docs/runner-strategy)。

## 前置条件

每个环境需要:

- `bash`、`tar`、`gzip` 和 `timeout`(coreutils)—— 每个任务都会用到。
- 构建与测试命令所需的工具链(cmake、编译器、python 等),由机器管理
  员自行安装。

环境**不需要 git**,也不需要任何仓库访问权限:服务器自行克隆代码
仓库,再把工作树传送过去。

## 标签

每个环境带有一个或多个**标签**(小写单词,如 cpu、gpu、cuda、mpi)。
标签是测试矩阵挑选环境的方式:矩阵条目列出所需的标签,md-builder 挑选
*一个* 标签覆盖全部要求的环境。规则:

- 匹配是超集匹配且大小写不敏感:拥有 cpu、mpi 标签的环境满足只要求
  cpu 的条目。
- 多余的无关标签不影响匹配;有多个候选时,"最紧凑" 的环境胜出(额外
  标签最少,其次按名称排序)。
- 每个条目只在一个环境上运行;若没有环境匹配,该条目被跳过(计入
  派发响应的 entriesSkipped,不算错误)。
- 环境**启用**后才能接收任务;停用的环境在仪表板上保持置灰。
